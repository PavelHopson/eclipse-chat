# Jarvis: локальная передача между устройствами

Статус: первый production-ready vertical slice реализован в Eclipse Desktop.
Протокол совместим с LocalSend v2 и работает напрямую в локальной сети без
загрузки файлов на сервер Eclipse Forge.

## Пользовательский сценарий

1. Открыть **Настройки → Интеграции → Jarvis · Передача рядом**.
2. Нажать **Найти рядом** и выбрать устройство с запущенным LocalSend.
3. Нажать **Выбрать файлы**. Системный desktop-picker не раскрывает webview
   абсолютные пути.
4. При необходимости ввести PIN получателя.
5. Нажать кнопку с явным именем устройства. Получатель подтверждает передачу
   на своём экране; Eclipse показывает прогресс, проверку и результат.

Входящие передачи в Eclipse Desktop пока выключены. Это осознанный безопасный
default: Jarvis не принимает файлы и не выполняет действия без решения
пользователя.

## Архитектура

- UI живёт в `apps/web`, но доступен только внутри доверенного Eclipse Desktop.
- Tauri capability разрешает пять узких native-команд только production-origin
  `https://app.star-crm.ru/eclipse-chat/*`.
- Native picker возвращает интерфейсу имя, MIME и размер; путь остаётся в Rust.
- Выбор хранится 15 минут под одноразовым UUID и потребляется при отправке.
- Discovery использует multicast LocalSend и ограниченный fallback-скан локальной
  `/24` сети. Ручной ввод IP отсутствует.
- Поддерживается только HTTPS. Сертификат получателя привязан к опубликованному
  fingerprint; подмена разрывает соединение до отправки тела.
- До передачи вычисляется SHA-256 каждого файла. LocalSend получателя проверяет
  хэш и отвечает `422`, если содержимое не совпало.
- Максимум 50 файлов и 20 ГБ за одну операцию; папки и symlink запрещены.
- Отмена использует отдельный `CancellationToken` конкретной передачи.

## Модель угроз и принятые решения

| Риск | Контроль |
| --- | --- |
| Скрытая отправка агентом | native-команда требует `confirmed=true`; UI показывает устройство и файлы до клика |
| Утечка локального пути | путь никогда не сериализуется в webview или журнал |
| Подмена устройства в LAN | HTTPS и certificate fingerprint pinning |
| Повреждение в пути | SHA-256 до отправки и обязательная проверка получателем |
| Повторное использование выбора | одноразовый selection UUID, TTL 15 минут |
| Отправка неожиданного типа | только обычные файлы; папки и symlink отклоняются |
| Зависание/массовая операция | лимиты файлов и размера, таймауты, отмена |
| Злоупотребление remote webview | command-specific Tauri permissions и allowlist production-origin |
| Нежелательный входящий файл | receiving отключён до отдельного sandbox/approval этапа |

## Jarvis — следующий слой

Jarvis может подготовить намерение: «найди телефон рядом и предложи отправить
отчёт». Он может открыть интеграцию и подсветить нужное действие, но не получает
доступ к путям и не подтверждает отправку вместо пользователя. Следующие этапы:

- входящий режим с quarantine, preview и отдельным подтверждением каждого файла;
- доверенные устройства с визуальной сверкой fingerprint;
- передача истории Eclipse Chat и экспортов Library как готовых пакетов;
- мобильный companion/PWA для нативного receive/share flow;
- журнал операций без имён файлов и персональных данных.

## Upstream

Вендорится только официальный Rust Core LocalSend на ревизии
`af0416be50770a97760f7070684bc667b759a15c`. Исходный Flutter-монорепозиторий не
скачивается в CI. Лицензия Apache-2.0 и ссылка на upstream лежат рядом с кодом в
`apps/desktop/src-tauri/vendor/localsend-core/`.
