## Findings

- Critical: none confirmed in this proportional review.
- High #37: fixed in source. The provisioner opens once with O_NOFOLLOW and
  O_NONBLOCK, checks the descriptor before reading, bounds bytes even on growth,
  rejects unsafe owner/mode/hardlinks and changed metadata, clears its byte buffer
  and always closes the descriptor. Unsupported platforms fail closed. The
  production preflight requires a root-owned, non-group/world-writable parent
  chain. POSIX integration tests cover symlinks and hardlinks; platform-independent
  descriptor tests cover ordering, limits, failures and cleanup.
- Scanner High #16: confirmed modulo bias (assessed Low hardening risk, not
  predictable passwords) removed with crypto.randomInt. #15/#17/#18 had uniform
  alphabets; explicit crypto APIs now remove the ambiguous modulo pattern.
  Tests use the real bot-key generator, not a copied formula.
- High #11–14: existing membership/role/database checks already constrained IDs.
  New disk basenames no longer contain request IDs or user filenames at all.
  Regression tests exercise traversal, Windows/absolute and encoded owner IDs.
  Existing file links and original filename metadata are preserved.
- High #19: nested entities are decoded in one pass. Regression tests cover
  nested ampersands and normal entities. LinkEmbedCard still uses React text,
  not an HTML sink; no confirmed XSS in that reviewed consumer.
- High #1–10 and Medium #33–36: reference documents under docs/Эффекты крутые,
  not production entry points or credential generation. No runtime import was
  found. Their scanner warnings are not silently dismissed; release artifacts
  must be checked to exclude those reference HTML/script files.
- Medium repository risk remains: master has no branch protection/rulesets.
  This release does not change repository settings. The production reviewer
  gate remains; both checkouts now reject stale, non-validated SHAs.

No token/password rotation is claimed or required by the changes above; existing
