# 00-144 — доступ к вложениям после исключения участника

## Что было

Вложения сообщений лежат в `uploads/attachments/` и раздавались **публичной
статикой**: nginx `location ^~ /eclipse-chat/uploads/` (alias на диск,
`Cache-Control: public, max-age=3600`) и в dev — `@fastify/static` на
`/uploads/`. Ни один из путей не проверял ни сессию, ни членство.
Кто однажды получил URL (сообщение, вкладка «Файлы», поиск, кэш SW или
браузера), читал файл навсегда — в том числе после исключения, выхода из
сервера или группы DM, понижения роли и даже без входа.

Заготовка под защищённую выдачу уже была (`auth/mediaSession.ts`: HttpOnly
media-cookie на `Path=/api/attachments/`, выдаётся на login/refresh), но
маршрута-потребителя не было.

## Что сделано

- `GET /api/attachments/media/:file` (`apps/server/src/routes/attachmentMedia.ts`)
  — единственный путь к байтам вложения. На каждом запросе:
  валидная media-cookie (живая refresh-сессия, не забанен/не удалён) →
  поиск `Attachment` по `messageId` из имени файла и точному `url` /
  `thumbnailUrl` → проверка **текущего** доступа к сообщению:
  канал — `Member` существует (+ internal-комната CLIENT-воркспейса только
  с `ROOM_VIEW_INTERNAL`), DM — участник беседы; удалённое и истёкшее
  исчезающее сообщение — нет доступа. Ответ `private, no-store`, CSP
  sandbox, CORP same-origin, nosniff; Range работает (перемотка медиа).
  «Нет файла» и «нет доступа» — одинаковый 404.
- Прямой путь закрыт: nginx `location ^~ /eclipse-chat/uploads/attachments/
  { return 404; }`, в Fastify-статике `allowedPath` (`isPublicUploadPath`,
  с нормализацией регистра/кодирования/`..`). Аватарки, иконки и баннеры
  серверов остаются публичными.
- Веб: `resolveAssetUrl` переписывает `/uploads/attachments/<file>` →
  `/api/attachments/media/<file>` (все 34 места рендера идут через него);
  `useMediaSessionKeeper` продлевает cookie (раз в 10 мин, при возврате во
  вкладку), SW не кэширует и не отдаёт из кэша старый путь.
- `deploy/scripts/smoke.sh` больше не берёт probe из `attachments/` и
  проверяет, что прямой URL вложения отвечает 404.

## Проверенные пути

| Путь | Итог |
| --- | --- |
| Прямой URL `/uploads/attachments/…` (nginx, Fastify static) | закрыт, 404 при любом написании |
| Новый API файла и миниатюры | только действующий участник; 404 после исключения/выхода/удаления из группы DM/понижения роли |
| Без входа / после logout, бана, удаления аккаунта | 401 (cookie привязана к живой refresh-сессии) |
| Подписанные/«секретные» ссылки | не используются; URL без доступа бесполезен |
| Кэш SW | старый путь в обход кэша; новый путь `/api/` SW не кэширует |
| HTTP-кэш браузера | `private, no-store` |
| Превью (миниатюры) | тот же маршрут и та же проверка |
| WebSocket | событий с байтами файла нет; при `leave` сокет выводится из комнат сервера (`removeServerRoom` + `reconcileUserServerRealtimeAccess`), новые URL ему не приходят |
| API, отдающие метаданные (сообщения, поиск, «Файлы», музыка, extract-actions) | проверяют членство; даже утёкший URL теперь не даёт байтов |

## Ограничения

- Маршрута «исключить участника» в master нет (ветка
  `feat/claude/member-kick` не влита). Защита не зависит от способа потери
  членства: проверяется наличие `Member` в момент запроса.
- Файл, уже скачанный на устройство, отозвать нельзя. Старый uploads-кэш SW
  (`eclipse-v1.7.92-uploads`) удаляется только бампом `SW_VERSION` —
  **обязательно при выпуске этого изменения**. Новый SW старый путь не
  отдаёт, но копии лежат в Cache Storage до бампа.

## Дополнение: обучающие видео и файлы таблиц

- `/uploads/training-videos/` был публичным. Теперь —
  `GET /api/attachments/training-videos/:file` (та же media-cookie; доступ —
  текущий участник сервера, как у `GET /api/servers/:id/training-library`;
  Range, `no-store`). Веб-резолвер переписывает URL, SW не кэширует.
- `/uploads/tables/` был публичным, хотя маршруты таблиц удалены в v1.6.48 и
  UI эти файлы не показывает. Теперь закрыт без замены (404). Файлы на
  диске не удалялись — это отдельное решение.
- nginx, Fastify static (`isPublicUploadPath`), smoke и тесты покрывают
  все три каталога.
- Боты (API-ключ) байты вложений не получают — как и раньше, им это не
  требовалось.
- Старые клиенты до обновления фронта увидят битые вложения (прямой путь
  закрыт); PWA/desktop/Android грузят удалённый фронт и обновятся сами.
