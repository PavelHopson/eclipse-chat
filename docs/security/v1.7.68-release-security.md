# v1.7.68 security disposition — 2026-08-30

Bounded release review of the changed authentication, session storage and UI
surface using the project's API/security checks and protected production workflow.
No production credentials were read or changed, no control was weakened to pass a
test and no scanner path or finding was suppressed.

## Findings

- Critical: none identified in the changed surface.
- High: none identified in the changed runtime surface.
- Medium, fixed and deployed: ordinary login previously revoked every refresh
  session for the user, causing another browser/application session to be logged
  out. Login no longer performs global revocation. Password change and recovery
  retain deliberate global revocation.
- Medium, fixed and deployed: ordinary logout previously revoked every refresh
  session. It now revokes only the submitted refresh token using the compound
  `tokenHash + userId` filter. A token belonging to another account cannot be used
  to terminate that account's session. Missing tokens from older clients degrade
  to local logout and access-token expiry instead of global logout.
- Medium, accepted residual: multi-account switching keeps multiple access and
  refresh token pairs in browser `localStorage`, extending the impact of a
  successful same-origin XSS compared with a single remembered account. No
  password is stored. Recommended follow-up is HttpOnly, Secure, SameSite web
  cookies and OS keychain-backed storage for the desktop wrapper.
- Low, accepted residual: removing a remembered inactive account removes its local
  tokens but does not immediately revoke that server refresh session. The existing
  Sessions and Devices flow can revoke it; password change/recovery revokes all.
- Medium, existing repository risk: `master` still has no branch protection and no
  repository ruleset (read-only verification on 2026-08-30). This release did not
  change repository settings. Exact-SHA deploy validation, production approval,
  verified backups and smoke gates remain in force.
- Existing CodeQL backlog: 14 open alerts remain only in reference/demo files under
  `docs/Эффекты крутые` (4 medium untrusted-source examples and 10 high insecure
  randomness examples). No open alert points to `apps/`, `deploy/` or production
  runtime code. They remain open and were not dismissed.
