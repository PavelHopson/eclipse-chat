# v1.7.67 security disposition — 2026-08-28

Bounded release review using the API security checklist and the existing project
security gates. No production credentials are read, no authorization is weakened,
no scanner finding is dismissed and no scan paths are excluded.

## Findings

- Critical: none identified in the changed surface.
- High, source fix deployed: changing microphone capture settings could call SDK enable
  before reapplying mute. Reconfiguration now defers while muted, deafened or in
  push-to-talk. A regression executes the actual hook callback for each state.
  Exact-SHA deployment and matching frontend assets are verified. Physical
  two-client runtime verification remains open; no end-to-end closure is claimed.
- Medium, source fixed: concurrent queue edits/add/skip could overwrite changes.
  Exact snapshots, positional edits, compare-and-swap and conflict responses now
  protect the affected operations. JWT, membership, host/moderation checks,
  strict bounded input and an edit rate limit remain server-side. Deleted or
  cross-workspace queue entries do not disclose their filenames.
- Low, source fixed: service-worker activation now deletes only Eclipse-owned
  old caches, preserving other applications sharing the origin. Vite modules
  bypass an old worker and development no longer installs the production worker.
- Medium, existing repository risk: master has no protection/rulesets (read-only
  verification on 2026-08-28). This release does not change repository settings;
  the production approval and exact-SHA checks remain in force.
- Low, existing/open: App.tsx hardReload still unregisters every service worker
  and deletes all CacheStorage entries on the origin. This can affect neighboring
  PWAs' offline caches. App.tsx was excluded from the release (local preview-only
  dirty changes), so the SW activate fix does not close this separate helper.
  No origin-wide cleanup was invoked during smoke; normal reload loaded v1.7.67.
