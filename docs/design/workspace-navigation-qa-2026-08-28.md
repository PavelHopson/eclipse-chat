# Workspace navigation — локальная реализация, 28 августа 2026

Все пять согласованных пунктов реализованы локально в Eclipse Chat. Ветка master; commit, push и deploy не выполнялись. Production v1.7.64 не менялся. Предыдущие dirty changes, задачи и обработчик выхода сохранены.

## Что сделано

1. **Обсуждения.** Настоящий ThreadPanel используется и в AppShell, и в DEV-preview. Источник сворачивается; доступны возврат к исходному сообщению, ответы и существующие вложения. На mobile это отдельный диалог со своим скроллом, удержанием фокуса и Escape. Отправка завершается по HTTP acknowledgement, не зависит от получения socket-события; оба подтверждения объединяются без дубликата. Ошибка сохраняет черновик и позволяет повторить отправку. Поздние ответы другого обсуждения не меняют текущую панель. После отправки фокус возвращается в поле, если пользователь ещё не перешёл к другому контролу.
2. **Поиск.** Сообщение, задача или метаданные файла открываются в предварительном просмотре рядом с результатами; на mobile — вместо списка с явной кнопкой назад. Запрос и фильтры сохраняются при возврате к результатам. Есть переход в переписку и обратный переход к прежнему видимому сообщению. Даты фильтров показываются в локальном часовом поясе. Быстрые переходы, семантический поиск и память сохранены. Это не новый полноэкранный медиаплеер.
3. **Непрочитанное.** Отдельно показаны новые сообщения, точные личные упоминания и новые ответы в обсуждениях. Собственные, удалённые и ожидающие отправки сообщения не увеличивают число новых входящих. Кнопка ведёт к первому непрочитанному из загруженного окна сообщений; счётчик не объявлен серверным глобальным inbox. При смене комнаты данные прошлого визита не переносятся из предыдущей.
4. **Фокус и ширина.** Новый режим скрывает вспомогательные панели, но не фильтрует переписку. Старый функциональный focus-фильтр не переопределён. Ширина обсуждения 320–560 px, с ограничением по доступному viewport: drag, стрелки, Home/End, двойной клик для сброса. Предпочтение сохраняется локально; фокус-режим при новом открытии приложения выключен. Drag обновляет CSS-переменную через requestAnimationFrame; состояние фиксируется после отпускания.
5. **Состояния.** Общие loading/empty/error/retry поверхности для обсуждений и поиска, отдельный статус подключения. При offline/reconnecting поле остаётся редактируемым, отправка недоступна. После восстановления не выполняется автоматическая повторная отправка. Новых API и зависимостей нет.

The Taste применён к рабочему интерфейсу: спокойные поверхности, читаемая иерархия и раскрытие вторичного по запросу. Использованы существующие Eclipse-токены и Phosphor. Motion ограничен короткими перемещениями и прозрачностью; reduced-motion отключает их. Постоянных декоративных анимаций в переписке не добавлено.

## Security и ограничения

Применён defensive API-security baseline. Существующие серверные JWT, членство в пространстве/канале, права задач и ограничения вложений не менялись. UI не используется как граница авторизации. Поиск выводит React-текст, без unsafe HTML; thread endpoints кодируют идентификатор. Ошибки не выводят raw HTTP payload или credentials в журнал. Предпочтение ширины — ограниченное число, не секрет.

- Critical / High / Medium / Low: новых подтверждённых security-находок в изменённой поверхности не выявлено. Это ограниченный review, не полный пентест.
- Типовые credential-паттерны не найдены в tracked diff и новых файлах navigation-слайса.
- DEV transport ограничен DEV + loopback + явным query-параметром, не отправляет неподдерживаемые запросы на реальный API и исключён из production JS. Созданные Blob URLs освобождаются.
- Исправления надёжности: зависание ответа в pending без socket, повторный submit, потеря фокуса после отправки, stale prior-visit данные другой комнаты, отсутствие понятного retry.
- Авторизованный production smoke, настоящий offline/reconnect на production-сессии и физическая мобильная клавиатура не проверялись. Они остаются release-проверкой, не подменяются демоданными.

QA выполнялся в отдельном чистом Chromium с заблокированными внешними запросами: встроенное браузерное подключение не ответило. Пользовательский browser profile, cookies и сессии не читались. Реальные UI-компоненты проверены на локальном mock-транспорте. Production-данные и инфраструктура не изменялись.
