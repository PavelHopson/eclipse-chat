# Личное оформление Eclipse Chat

Решение пользователя от 2026-09-05. Заменяет прежнее требование двух тем.

- Единственная основа — тёмная OBSIDIAN. Переключателя SOLAR нет; старое значение в localStorage игнорируется. Исторические светлые CSS-селекторы пока не удаляем, но продукт их не активирует.
- Настройки → Оформление: основной и второй акценты, фон, панели, текст, границы. Готовые палитры служат отправной точкой; каждый HEX можно изменить вручную.
- Цвета личные, не публичная карточка профиля и не настройки пространства. Приоритет: личная палитра → бренд пространства → стандартные токены.
- Статусы, ошибки, присутствие, изображения и сам видеоконтент не перекрашиваются. Производные состояния и вторичный текст рассчитываются автоматически. Основа остаётся тёмной; нечитаемый текст нельзя сохранить.
- Предпросмотр меняет текущий интерфейс, но не сервер. «Отменить» и закрытие редактора возвращают сохранённую палитру. «Сбросить» выбирает стандартный вид; сброс тоже нужно сохранить.
- Источник истины — отдельная таблица `UserAppearance`, доступ только через JWT-владельца в GET/PUT `/api/users/me/appearance`. В тело запроса нельзя передать чужой userId. JSON ограничен шестью HEX-цветами или `palette: null`.
- Локальный кэш `eclipse:appearance:v1:<userId>` ускоряет запуск и раздельный вход в аккаунты. Веб и приложение получают серверную настройку при входе и возвращении фокуса; активный предпросмотр не перезаписывается. Одновременные сохранения: последнее подтверждённое сервером значение побеждает.
- Изменение цвета не должно добавлять анимацию всего экрана. Клавиатурный фокус и существующее уменьшение движения сохраняются.

Для выпуска нужна миграция `20260905120000_private_appearance` до обновления сервера и веб-клиента. Добавление таблицы не затрагивает сообщения, задачи, медиа и голосовые сессии.

Согласованная 2026-09-05 граница выпуска: обычный release Chat не резервирует БД StarCRM и не развёртывает AI Hub/Office integration secrets. Текущие интеграции продолжают использовать существующую конфигурацию; их provision/rotation выполняются отдельно по явному разрешению. Обязательные Chat backup, approval, exact-SHA, migration и rollback остаются.
