# Eclipse Chat — media workbench, 2026-08-28

Статус: реализовано и проверено локально. Commit, push и production deploy не выполнялись.
Этот отчёт дополняет workspace-interactions-2026-08-28.md, а не заменяет его исторические результаты.

## Согласованный список

1. Быстрый выбор микрофона и выхода рядом с кнопками звонка. Открытие меню только перечисляет устройства, не запрашивает запись. Есть недоступное устройство, системный выход, обновление списка, фокус и Escape.
2. Компактные участники аудиозвонка с отдельным сохранением выбора для каждой комнаты. Чат получает больше места; ширина ограничивается доступным пространством. При появлении видео сцена получает приоритет.
3. Более читаемые авторы и время; обычный AI_AGENT без фиолетовой декоративной рамки. Специализированные роли ботов и их подписи сохранены.
4. Поднять, опустить и удалить конкретную позицию очереди, включая одинаковые треки. Только ведущий/существующие роли модерации; сервер проверяет точный снимок очереди и compare-and-swap. Добавление и переход к следующему треку также не затирают конкурентное редактирование.
5. Вписать / 100% для видео и демонстрации экрана; панорамирование исходного размера, обычная прокрутка и клавиатура. Масштабирование не пересоздаёт медиатрек.
6. Единый переход play/pause, короткая обратная связь перемотки и скорости, состояния ожидания/ошибки/завершения. Реактивная визуализация общего аудио использует анализатор; без данных нет выдуманной волны. Существующие локальные звуки действий сохранены с отдельной громкостью и выключателем.
7. Геометрия расширенного плеера перенесена в media-workbench.css; устранены конфликтующие правила компактных участников и небезопасное центрирование переполненного списка. Добавлены регрессионные контракты и матрица визуальной проверки.

## Аудио и видео

- Общий мини-плеер и расширенный плеер различают команды ведущего и локальное прослушивание/громкость. Смена скорости доступна только локальным вложениям, не общей сессии.
- Локальное видео: временная шкала, буфер, шаг ±10 секунд, скорость, громкость, fullscreen, PiP при поддержке браузером, повтор при ошибке.
- Локальное аудио: временная шкала/реальные сохранённые peaks, скорость, громкость, состояние загрузки и повтор.
- На mobile высота видео учитывает пропорции источника. Горизонтальный ролик больше не окружён огромными пустыми полями.
- Транспорт общего плеера остаётся виден, прокручивается только список очереди/аудиотеки.

## Визуальный контракт

Применены The Taste, accessible-animation и 60fps-animation: плотный рабочий интерфейс, графит и золото Eclipse, один главный акцент, анимация объясняет изменение состояния. Без новых библиотек и декоративных фоновых эффектов внутри переписки.

- Короткие переходы transform/opacity; очередь — ограниченный FLIP-переход.
- Системное reduced motion и настройка «Анимации интерфейса» останавливают декоративное движение; фокус и состояния остаются видимыми.
- Нативный курсор на медиаконтролах, вводе, меню устройств и resize.
- Кнопки задач, пять типов задач, переписка, загрузки и обработчик выхода сохранены.
- Это компонентная консолидация, не переписывание всей исторической CSS-системы. AppShell CSS пока около 705 KB / 104 KB gzip; формальная сертификация FPS не проводилась.

## Security / ограничения релиза

- Critical: в изменённом объёме не обнаружено.
- High, исправлено локально: обновление настроек могло вызвать SDK enable для уже заглушённого микрофона до повторного mute. Теперь конфигурация откладывается при mute/deafen/PTT; тест исполняет настоящий callback хука. Runtime-подтверждение на двух устройствах ещё требуется, production-исправление не заявляется.
- Medium, исправлено локально: конкурентные skip/add/edit могли затереть очередь. Добавлены CAS, проверка снимка/позиции, membership, host/moderation и тесты конфликтов. Имена недоступных/чужих файлов не раскрываются.
- Low, исправлено локально: service worker больше не очищает кэши других продуктов того же origin. DEV не регистрирует production SW; старый worker пропускает Vite-модули в сеть.
- Новых зависимостей, секретов, внешних сервисов и ослаблений авторизации нет. Это пропорциональная проверка diff, не полный pentest.

Перед публикацией: реальный двухклиентский LiveKit-тест, смена устройств при mute/PTT, восстановление соединения, native Windows, реальные permission/autoplay-denied сценарии, прослушивание сигналов в наушниках. После отдельного разрешения на release — штатные CI/deploy/точный bundle smoke.
